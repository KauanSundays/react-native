## Checklist do Fantasy Draft App

### Etapa 1: Tipagem e Contratos (`types.ts`)

* [ x ] `interface Player` contendo: `id` (string), `name` (string), `position` (string), `price` (number) e `isDrafted?: boolean`.
* [ x ] Interface Genérica `ApiResponse<T>` contendo: `data: T`, `status: number`, `message?: string`.
* [ x ] Interface/Type `ApiError` contendo: `message: string`.
* [ x ] Type Guard `isApiError(error: unknown): error is ApiError` utilizando os operadores `in` e `typeof`.

---

### Etapa 2: Camada de Dados & Custom Hook (`usePlayers.ts`)

* [ x ] Mock de dados com pelo menos 6 a 8 jogadores tipados como `Player[]`.
* [ x ] Estados do Hook: `players` (`Player[]`), `loading` (`boolean`), `error` (`string | null`).
* [ x ] `useEffect` simulando chamada HTTP com `Promise` + `setTimeout` (1.5 segundos).
* [ x ] Bloco `try/catch/finally` utilizando o Type Guard `isApiError` para capturar exceções.
* [ x ] Retorno do hook: `{ players, loading, error }`.

---

### Etapa 3: Componente Leaf Memorizado (`PlayerCard.tsx`)

* [ x ] Interface `PlayerCardProps` tipando as props: `player` (`Player`), `isDrafted` (`boolean`), `onToggleDraft` (`(id: string) => void`).
* [ x ] Inclusão de `console.log(`[RENDER] PlayerCard: ${player.name}`)` no topo do componente para monitorar re-renders.
* [ x ] Layout do Card: Nome do jogador, posição, valor do contrato e botão dinâmico ("Contratar" / "Dispensar").
* [ x ] Export do componente envelopado com `React.memo`.

---

### Etapa 4: Tela Principal & Performance (`App.tsx`)

* [ x ] Consumo do Custom Hook: `const { players, loading, error } = usePlayers()`.
* [ x ] Estado local `search` (string) conectado ao `TextInput`.
* [ x ] Estado local `myTeam` (`string[]`) guardando os IDs dos jogadores contratados.
* [ x ] `useMemo` para `filteredPlayers`: filtrando a lista por nome com `.filter()`.
* [ x ] `useMemo` para `totalCost`: calculando o custo total do time atual com `.reduce()`.
* [ x ] `useCallback` para a função `handleToggleDraft`: alterando o estado `myTeam` com atualização funcional (`prev => ...`) e Spread Operator.
* [ x ] Header com o Painel do GM (Total de contratados e Folha Salarial).
* [ x ] Renderização da lista através do `FlatList`.

---

### Etapa 5: Validação e Regra de Ouro da Performance

* [ ] **Zero `any`:** Nenhum arquivo possui o tipo `any`.
* [ ] **O Teste de Ouro:** Ao abrir o app e digitar qualquer texto no campo de busca, os cards que continuam na tela **não exibem** novos logs de `[RENDER]` no console.
